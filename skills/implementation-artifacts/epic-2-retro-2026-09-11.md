## Findings

- **A self-terminating `claude` process silently starts a new conversation on the next reattach.** If `claude` inside `claude-<workspace>` exits or crashes on its own, its tmux pane closes with it, and the next `connect.sh` begins a fresh conversation rather than resuming. This is G3's most common failure mode and is currently neither documented nor handled.
  Source: `deferred-work.md`, story 2.4 entry; inherent to `start-claude.sh`'s `exec claude` launch pattern from story 2.1.
  Disposition: **fix now** — action item 2 in the epic-3 document.
- **A `WORKSPACES_DIR` injection surface was found and closed during story 2.1's review**, via `printf %q` escaping. Recorded as a win: the adversarial review layer caught a real security defect that the implementation pass had introduced.
  Source: story 2.1 review triage (7 findings patched, 6 deferred).
- **PRD FR10 wording is stale** — describes `tailscale status --json` parsing while the implementation uses plain text per AD-8. Spec reconciliation, proposed as action item 4.
- **`cp config/tmux.conf.example ~/.tmux.conf` overwrites an existing file without warning.** Disposition: **defer**.

## Behavior verification

Verified: all four scripts' self-tests pass; `start-claude.sh` never emits
`--dangerously-skip-permissions`, `bypassPermissions` or `--add-dir` (FR5, FR16,
asserted by its own test case); a detached tmux session survives and preserves
scrollback on reattach; `config/tmux.conf.example` loads cleanly.

**Not verified — the material gap:** story 2.4's final AC, the M1 protocol on two
real nodes (A→B, kill link, reconnect under 60s with context intact; then B→A
coexisting). It was never executed: one machine, no second tailnet node. No
result was fabricated — the spec's Verification section states the gap, and the
owner accepted promotion with the debt recorded (`deferred-work.md`, PR #29).
