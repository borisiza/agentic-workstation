## Findings

### Aggregate view: god-file / size growth

- **`scripts/doctor.sh` is the largest artifact at 1352 lines** (top of the churn ranking, +1352 net across 2 commits). Inspected rather than judged on churn alone: **~733 lines (54%) are the embedded self-test suite**, leaving ~619 lines of operational logic across 54 functions. Not a god-file; large because the test harness lives in the same file by design.
  Source: `scripts/doctor.sh`; `git_evidence.py` range `d0c731d^..80d09f3`.
  Disposition: **accept as-is**.
- **Every script is >53% embedded self-test**: connect.sh 58%, start-claude.sh 59%, stop.sh 56%, status.sh 54%, doctor.sh 54%, enroll.sh 53%. 4368 total script lines, roughly 2440 of them test code.
  Source: `scripts/*.sh`.
  Disposition: **accept as-is** — this is AD-8's consequence (bash 3.2, no test framework, no dependencies). Worth naming so a future reader does not mistake the line counts for logic volume.

### Aggregate view: duplication map

- **The self-test assertion harness is replicated across all six scripts**: `assert_exit_eq`, `assert_stderr_one_line` (6 copies each), `assert_file_absent`, `selftest_case_help`, `selftest_case_broken_config`, `write_stub_tools` (5 each), `assert_file_contains` (4), plus `usage`, `main`, `run_self_test`, `die2` in all 6.
  Source: function-name census across `scripts/*.sh`.
  Disposition: **accept as-is** — ARCHITECTURE-SPINE.md:31 declares `scripts/` is "one file per verb, **no shared library**". The duplication is the deliberate cost of that decision, not a story-level defect.
  Upstream lesson: the decision is sound for distribution (each script is copy-one-file portable) but it means **a fix to the assertion harness requires six edits**. Worth revisiting only if harness churn becomes real.
- **`die2` is byte-identical in all six scripts** (same md5), while **`resolve_and_validate_role` diverges in all six** (six distinct md5s). Most divergence is legitimate: each names its own binary in the error text, and `doctor.sh` accepts `client` because it runs under any role while `status.sh`/`stop.sh` accept only `host|both`.
  Source: `sed`-extracted function bodies, `scripts/*.sh`.
  Disposition: **accept as-is** for the intentional divergence.

### Aggregate view: pattern divergence

- **Config sourcing diverges in error visibility.** `doctor.sh` sources the role config with `. "$CONFIG_FILE"`, while `status.sh` (and siblings) use `. "$CONFIG_FILE" 2>/dev/null`. A `config/local.env` with a syntax error is therefore reported by one script and silently swallowed by another, for the same broken file.
  Source: `scripts/doctor.sh` vs `scripts/status.sh`, `resolve_and_validate_role`.
  Disposition: **fix now** (small, and it is a diagnosability bug the user hits exactly when something is already wrong).

### Aggregate view: spec-to-implementation reconciliation

- **FR16 (workspace isolation) is implemented but unlabelled.** A literal `FR16` search returns zero hits in `scripts/`, `docs/`, and the story specs, which initially reads as a dropped requirement. The behavior is present: `start-claude.sh` builds `cd "$dir" && exec claude -n "$session" --permission-mode default`, never passes `--add-dir`, and a self-test case asserts `--add-dir` is absent from argv.
  Source: `scripts/start-claude.sh:127`, `:226`; `skills/planning-artifacts/epics.md:103,116,324`.
  Disposition: **accept as-is**. Note the isolation is cwd-scoped plus absence of `--add-dir`, not an enforced allowlist — which is what the AC specified.
- **PRD FR10 still describes host discovery as parsing `tailscale status --json`**, contradicting AD-8 ("no jq") and the plain-text parsing actually implemented in `connect.sh`.
  Source: `skills/implementation-artifacts/deferred-work.md` (story 2.3 entry); `prd.md` FR10.
  Disposition: **spec reconciliation, proposed** — the implementation is correct; the PRD wording is stale.

### Carried findings from story-level reviews (deferred-work.md)

Each story ran three adversarial review layers during the loop; findings triaged `patch` were applied in-story, `defer` entries landed in `deferred-work.md`. The ones that matter beyond their own story:

- **A self-terminating `claude` process silently starts a new conversation on the next reattach.** If the `claude` process inside `claude-<workspace>` exits or crashes on its own (not via reboot or `stop.sh`), its tmux pane closes with it, so the next `connect.sh` reattach begins a brand-new conversation instead of resuming. This erodes G3 in its most common failure mode — a crash — and is neither documented nor handled.
  Source: `deferred-work.md`, story 2.4 entry (edge-case-hunter); inherent to `start-claude.sh`'s `exec claude` pattern from story 2.1.
  Disposition: **fix now** (at minimum document it; ideally detect it).
- **`config/local.env` is sourced as shell code**, so anything written there executes with the user's privileges. Mitigated only by file permissions, which `doctor.sh` checks.
  Source: `deferred-work.md`, story 1.2 entry.
  Disposition: **defer**, tracked — acceptable for a single-user MVP whose config is `0600`, but it is a real execution surface.
- **`cp config/tmux.conf.example ~/.tmux.conf` silently overwrites an existing `~/.tmux.conf`.** Same unguarded-`cp` pattern accepted elsewhere in the onboarding docs.
  Source: `deferred-work.md`, story 2.4 entry.
  Disposition: **defer**.

## Behavior verification

Exercised end to end on this machine:

- **All six self-tests pass**: `connect.sh`, `doctor.sh`, `enroll.sh`, `start-claude.sh`, `status.sh`, `stop.sh` each return PASS on `--check`.
- **The cross-story contract holds**: `doctor.sh --check` discovers and aggregates the `--check` of all five sibling scripts (`PASS other-script:connect.sh`, `enroll.sh`, `start-claude.sh`, `status.sh`, `stop.sh`). This is the one integration point every story depended on and no single story owned.
- **Role gating works both ways**: with `FALLBACK_SSHD=0` the three fallback checks report SKIP; with `FALLBACK_SSHD=1`, `tailscale-ssh-advertised` and `platform-contract` flip to SKIP and the fallback checks activate, correctly reporting FAIL on this machine (no Remote Login, no `authorized_keys`).
- **tmux persistence**: a detached session survives and its scrollback is preserved on reattach; `config/tmux.conf.example` loads without error.
- **Secret hygiene**: `gitleaks git . -v` reports zero findings across the full history; `pre-commit run --all-files` passes; a staged private key is blocked and redacted. The four `gitleaks dir` hits are false positives — SHA-256 checksums in `_bmad/_config/files-manifest.csv`, a file that is not tracked and never reaches the public repo.
- **`enroll.sh` key handling**: handles only `.pub` material, never private keys; applies `chmod 700` to `~/.ssh` and `600` to `authorized_keys` (FR15).

**Not exercised — the material gap:** anything requiring a second tailnet node. See the verdict.

## Acceptance verdict

**accepted-with-open-items** — criteria **declared** (12 AC blocks in `epics.md`).

Evidence for acceptance: all 12 stories are `done` with `pending_stories: []` across all three epics; every declared AC that is verifiable on a single machine was checked and passes (self-tests, cross-script aggregation, role gating, secret hygiene, permissions, tmux persistence); CI `hygiene` was green on all 33 PRs.

Evidence for the open items: **story 2.4's final AC — "the M1 protocol executed on two real nodes" — was never executed.** The build environment has one machine and no second tailnet node. No result was fabricated; the story spec's own Verification section states the gap explicitly, and the owner accepted promotion with the debt recorded (`deferred-work.md`, PR #29). The consequence is precise and worth stating plainly: **G3 and NFR2 — that a dropped link never costs a session — have no empirical evidence.** The same holds for epic 3: `enroll.sh` and `connect.sh --fallback` have never run against a real fallback host.

This is a human decision overriding the machine reading, recorded per rule 1. What the sprint demonstrably delivered is a complete, self-tested, hygiene-gated implementation; what it has **not** demonstrated is the product promise itself.
